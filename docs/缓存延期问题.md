## 一、来自缓存重构评审的小问题(9 项)

这些是评审发现、判定为**非阻塞**而延期的问题。均不影响常规播放 / 下载 / 离线;
标注了各自的触发条件与后果。

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| M1 | 封面驱逐缺引用保护 | `audio_cache_store.dart` `ensureSpace` 驱逐循环 | 当前不可达;若将来两行共享同一 `cover_path`,会误删另一行仍在用的封面 |
| M2 | 写入封面后 `enforceLimit` 可能驱逐那一行 | `cover_service.dart` `_writeLayer1Cover` | 低概率;返回的封面路径随即被删、`tracks.cover_path` 悬空,靠 `existsSync` 自愈 |
| M3 | `_inFlightByUrl` 不再覆盖层 1 路径 + 文档过时 | `cover_service.dart` 类注释 / `_inFlightByUrl` / 层 1 下载分支 | 多分 P 共用同一 `pic` 且音频都已缓存时,同一张图可能下载两次;注释误导 |
| M4 | 复用封面字节跳过解码校验 | `cover_service.dart` `_bytesOf` 复用路径 | 仅当文件事后被外部损坏时,坏图会被写进层 1,直到 `force` 刷新;与既有行为一致 |
| M5 | 清空离线缓存的成功提示不区分失败 | `offline_cache_providers.dart` `onClearAll` + `settings_screen.dart` `_confirmClearOffline` | 删除失败仍弹"已释放";数值为清空前读取,可能偏大;不损坏数据 |
| M6 | 离线列表标题用原始 `sourceTrackId` | `settings_screen.dart` 离线区块标题与确认框 | 显示裸 ID(如 `BV1xxx:123`)而非歌名/歌手,可读性差;纯 UX |
| M7 | 四个近似确认弹窗 | `settings_screen.dart`(删单条 / 清空离线 / 清空缓存 / 删扫描根) | 无功能问题;改文案或样式需同步四处,易漂移;纯维护性 |
| M8 | 层 2 搬迁被启动清空白做 | `cache_relocator.dart` `_relocateCovers` + `main.dart` 启动 `coverCacheStore.clear()` | 升级启动时先搬旧 `cover_cache/` 再整体清空——搬完即删,纯浪费 I/O;旧目录留空 |
| M9 | `insert` 用不可读文件 upsert 仍覆盖 `filePath`/`bytes` | `audio_cache_store.dart` `insert` | 罕见;该行指向不存在文件,下次 `checkIntegrity` 删行,其间 `totalBytes` 计入配额;自愈临时脏状态 |

### 细节补充

- **M1**:音频删除前会查 `stillReferenced`(同一物理文件是否还被别的行引用),随行封面却是无条件删除。
  `coverFileFor` 按 `sha1(source:trackId)` 命名、表有 `UNIQUE(source, source_track_id)`,正常路径下每行封面唯一,
  因此**当前不可达**。修法是给封面删除加同样的引用检查,或补一行说明"为何无需检查"。
- **M2**:`_writeLayer1Cover` 末尾立即 `enforceLimit()`(= `ensureSpace(0)`)。仅当该行非 pinned、
  加上封面字节后恰好超限、且它恰为 LRU 最旧一行时触发。可行修法:写入后先确认文件仍在,或跳过自驱逐。
- **M5**:`onClearAll` 逐条删除、单条失败只 `debugPrint`;设置页无论成败都弹提示。
- **M8**:层 2 本就是会话级缓存,启动即清空,搬迁纯属多余;可改为直接删除旧目录。
